# AutoCoding Machine v2

轻量、可组合的 Python Agent Framework。调用方提供模型、工具和业务规则，框架负责执行循环、权限审批、会话记录、上下文管理和运行事件。Coding CLI 是建立在框架上的一个应用，内置 `coding`、`review`、`companion` 三套 Profile，可以在终端界面中使用，也可以通过 ACP 协议接入编辑器。

## 当前状态

v2 处于设计完成、开始实现的阶段：

- 架构、模块边界和关键决定已经确定，见 [v2 架构](docs/architecture.md)。
- 实现分为 15 个阶段，先打通最小可运行链路，再逐个模块加深，见[开发计划](docs/plan.md)。
- 验收标准是[行为契约](docs/behavior-contracts.md)：18 组带编号的规则，v2 的测试按这些规则编写，全部通过才算完成。
- 仓库中的代码和测试目前仍是 v1，从开发计划的阶段 0 开始替换。

## 设计要点

- **核心不依赖应用。**执行核心、工具注册、权限规则、会话与上下文、记忆、MCP 客户端、执行环境、模型网关是框架本身；Coding 应用、Textual 界面和 ACP 服务端通过扩展点接入，依赖只能从应用指向框架。
- **模型网关。**支持 OpenAI 兼容与 Anthropic 接口，收到回复前对临时错误自动重试，可以切换备用模型，统计用量与费用。
- **隔离执行。**工具通过执行环境操作文件和命令，可以选择在 Docker 容器中运行，只挂载工作区并默认关闭网络。
- **会话记录只追加。**用户消息、助手回复、工具回执和压缩摘要都作为记录追加，已有记录不改写；恢复会话时从最近一次压缩摘要继续。
- **权限只在一处判断。**规则按优先级匹配，给出允许、询问或拒绝；需要询问时任务暂停，由宿主显式提交决定。
- **每个工具调用都有回执。**一次模型回复中的工具调用按顺序处理；取消、拒绝和写入失败都有明确结果。
- **事件只通知，不控制执行。**界面和外部程序通过同一种事件订阅观察运行过程，收到的是脱敏后的视图。

## 开发

需要 Python 3.11 或更新版本和 [uv](https://docs.astral.sh/uv/)。

```powershell
uv sync
uv run pytest -q
```

模型配置写在本地 `.env`，模板见 `.env.example`；密钥不要提交到仓库。
