# ADR 0001：Harness 公共事件与权限交接约定

状态：已实现（2026-09-24）；具体验收记录见[实施计划](../plans/2026-09-24-harness-public-events.md)。

## 背景

外部程序需要知道运行何时暂停、权限决定是什么以及工具最终结果如何，同时不能通过事件替用户批准操作。当前内部 `permission_required` 事件包含原始工具参数，不能原样作为公共事件暴露；见 [MachineLoop](../../src/auto_coding_machine/engine/machine_loop.py)。

## 决定

- 在打开会话时注册会话级 `on_event` 回调，之后该会话的各次运行都通过它通知宿主；回调参数使用公共类型 `AgentEvent`。回调是观察方：其返回值不控制运行，回调异常不能中断 Agent。
- 事件名和对外字符串值使用小写 `snake_case`；Python 枚举成员可继续使用大写常量名。
- `permission_required` 表示运行已暂停并等待决定。事件和暂停结果暴露安全的权限请求视图，不暴露原始工具参数；宿主通过显式调用 `run.resolve_permission(approved=...)` 传入决定。Harness 随后单独发出 `permission_resolved`，其决定值为 `approved` 或 `denied`。批准只表示获准尝试，不代表工具执行成功。
- `Run Result` 继续通过运行返回值交付；事件用于通知过程变化，两者不互相替代。
- 对外事件、暂停结果、日志和未来传输只提供安全视图：摘要及理解操作所需的详情，长内容和敏感值在离开 Harness 前遮盖。原始工具参数留在内部执行路径中。
- 保留同步回调，不在本约定中增加异步事件流或 SSE；未来需要时可由外层适配。

## 取舍

把决定交给回调虽然可以少一次显式调用，但会混淆“观察事件”和“控制执行”，因此不采用。会话级回调使调用方只需注册一次；如果未来需要并行运行或独立路由，再评估是否增加运行级订阅。
