## 三件事分别负责什么

- Todo：保存步骤和进度，普通会话也能使用。
- Goal：保存目标与验收条件，决定自动继续、暂停或完成。
- 上下文管理：精简旧消息，同时保留准确的目标、约束与当前步骤。

Profile 决定使用哪些能力，Plan 用来先讨论方案；它们不替代任务状态。

## 按这个顺序实现

### 1. Todo 与恢复

步骤先只存编号、描述、状态和可选阻塞原因。状态包括待处理、进行中、完成、阻塞。提供任务更新工具和 `/todo` 展示，不先做依赖图或并行调度。

建议每个 session 配一个小型 `<session-id>.state.json`，只保存目标、步骤和累计预算；原始聊天继续保存在 JSONL。临时文件替换保证状态更新完整，保存失败必须明确提示。`/resume` 恢复步骤，历史状态不能当作操作已经成功的证据。

验收：更新后重启仍可恢复；不同 Profile 不串状态；压缩历史后 Todo 不丢失；没有任务时无需生成状态文件。

### 2. Goal 的继续与停止

候选命令为 `/goal <目标>`、`/goal`、`/goal pause`、`/goal resume`。目标与验收条件由用户要求确定；模型可维护步骤，不能擅自删掉验收条件。

Runtime 调度现有 MachineLoop，不新建另一套工具循环。完成验证复用现有证据，但一次测试通过不代表整个需求达成。Todo 全部勾选也不能直接宣告成功。

整个 Goal 共享轮数、耗时等预算，自动继续与暂停恢复不能重置已消耗值。预算耗尽、用户取消、缺少权限或必要信息、反复没有进展时停止自动推进，说明已完成和剩余工作。无进展阈值在实施前结合现有 Guard 确定，不把多次重复回答算成进展。

验收：提前宣告完成会被退回；实际完成可正常停；取消有效；预算跨继续累计；权限等待仍沿用既有检查；恢复旧 session 先暂停，用户继续后才执行。

### 3. 上下文优化与实测

先统计系统提示词、工具定义、历史和工具结果的占用，区分本地估算与服务端用量。然后精简旧的大段工具结果，保留原文引用并能按需取回，不复制另一份完整聊天。

最后改进历史摘要，保存关键文件、事实和验证结果。目标与 Todo 从任务状态重新注入，不依赖有损摘要记住它们。精简必须保持工具调用与结果的配对关系，并对最终请求检查预算。

沿用已有评测框架（实施前定位实际入口），对比当前版本、工具结果瘦身、加任务摘要三组。固定模型、任务与预算，重复执行；统计成功率、约束遗漏、提前停止、重复操作、总输入 token 和包含摘要开销的总耗时。

离线回放验证结构和信息保留，真实执行验证任务效果。没有实测之前，不填成功率或性能提升数字。
