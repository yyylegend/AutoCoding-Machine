# 模块化 Harness 与插件适配计划

状态：方向已确认；公共接口、插件契约和实现均待设计。本文是目标与范围，不代表当前代码已支持插件。

[规划入口](README.md) · [当前架构](../architecture.md) · [运行时边界基础计划](2026-09-05-runtime-boundaries.md)

## 想做成什么

把 Agent 看成 LLM 加 Harness：LLM 负责生成下一步，Harness 负责执行循环、会话、上下文、权限和工具。Harness 像一块有标准插槽的底板；Profile 是组合配方，Adapter 把具体实现接到插槽上。

未来结构的概念图：

```text
CLI / 未来的其他入口
  → Runtime 组装入口
      → AgentSession：一段对话
          → AgentRun：一次任务
              → MachineLoop：模型与工具循环
                  ↔ Model / Tools / Memory / SessionStore 等适配器

Profile：选择已有能力和策略，不承载插件代码
```

这是演进目标，不要求照此新增目录或一次性重写现有循环。对外接口应尽量少；模块内部可以组合更多实现细节。

## 先做一个真实插槽：外部记忆

首个外部记忆参考是 [TencentDB Agent Memory / MemoryCore](https://github.com/TencentCloud/TencentDB-Agent-Memory)。它作为独立记忆服务，通过 Gateway / SDK 接入；Harness 侧实现薄 Adapter，不让 Engine 依赖腾讯 SDK 或数据结构。

记忆插槽的职责先限定为两件事：

1. 模型请求前，按用户问题与明确的身份范围召回少量记忆，并在上下文预算内加入临时请求视图。
2. 任务完成后，按显式策略写回可复用的信息。先验证只读召回，再启用写回。

本地 SessionStore 继续负责保存原始会话和恢复任务；外部 MemoryProvider 负责跨会话或团队共享的长期记忆。两者职责不同，不能因为接入外部记忆就丢弃本地会话记录。

腾讯适配器需要提供团队、Agent、用户等作用域；密钥从环境变量或安全配置读取，不放进 Profile YAML。召回内容有明确条数 / token 上限，并作为外部数据处理，不能提升工具权限或覆盖系统策略。

## 插件与配置边界

- Profile 是配方：选择已经安装并允许使用的工具、策略和适配器。
- Adapter 是转接头：把统一的小接口翻译成具体模型、存储或外部记忆服务的调用。
- 插件故障有明确降级策略：可选记忆不可用时，Agent 可以不带记忆继续；写回失败必须可见，不能假报成功。
- 第一版显式安装、显式启用插件；配置只能引用允许的插件标识，不能从 YAML 任意导入 Python 代码。
- 暂不建设插件市场、自动下载、跨进程沙箱或通用工作流引擎。只有出现第二个真实实现和具体需求后，再决定是否需要更通用的插件发现机制。

## 建议实施顺序

1. **收紧现有生命周期契约。** 统一任务结果、权限暂停与恢复、取消，以及工具副作用后持久化失败时的行为；外部扩展错误不能让这些语义变得含糊。
2. **确定最小公共使用路径。** 让现有 CLI 成为第一个调用者，并增加一个无界面示例或测试调用者；调用方不需要自行拼装内部所有对象。
3. **定义 MemoryProvider 的小接口和测试替身。** 约定身份作用域、召回预算、结果来源、超时和失败语义；先做只读召回。
4. **实现腾讯记忆 Adapter。** 用 SDK 或 HTTP 接口连接 MemoryCore；验证作用域隔离、上下文上限、服务不可用时的降级和本地 JSONL 不变。
5. **增加显式写回。** 用户可选择是否启用，定义保留 / 删除行为，并让写回失败可见。验证稳定后再考虑其他插件。

## 验收标准

- 不配置外部插件时，现有 Coding / Review / Companion 行为保持不变。
- Engine 与 MachineLoop 不直接导入腾讯 SDK、HTTP 路径或外部记忆数据类型。
- 替换记忆 Adapter 不要求修改 CLI 或 MachineLoop。
- 召回严格遵守用户 / 团队作用域和上下文预算；召回结果不会被写进原始 Session JSONL。
- 记忆服务故障不会悄悄变成空成功；读取可降级，写入失败会明确报告。
- 至少有一个无界面使用示例和通过公共接口验证的 Adapter 契约测试。
